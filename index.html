Error tracking

Unhandled = non-fatal crash report via track_errors(). Handled = Countly.log_error().

Performance

Sends an APM network trace for /api/returns/submit (~2.4 s) via report_trace().

Identity

Reset = new hashed account id, then reload — a brand-new user. Clear queue = drop requests the SDK is still holding from an earlier run (use this if you see stale 400s).

Filing back end

When on, submitting a return fires filing_submission_failed instead of filing_submitted.

Experiment

In-app messages

Sends the trigger event; Countly shows the message in ~15 s, in the portal's language. Most messages show once per visitor (the rating every time) — use Reset device id for a fresh visitor. Crash recovery: use Throw unhandled JS error (~5 min).
